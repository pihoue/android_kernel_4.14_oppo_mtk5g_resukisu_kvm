 GPT（分区表）改动详解 —— 让 KVM 能运行的核心步骤
==============================================================================
设备: OPPO A55 5G (PFVM10 / MT6833)    改动日期: 2026-09-11
涉及文件:
  gpt/pgpt4k_orig.bin     原厂 GPT 前 256 KB (262,144 B)  MD5 5b4cffd99cf0d40e9038ba870024e985
  gpt/pgpt4k_nogz.bin     改好的 GPT 前 256 KB (262,144 B) MD5 c3fdbe48dccb5ceae2dfeebec1e87398  ← 要刷的
  gpt/pgpt-raw-17408B.bin 另一种尺寸的 GPT 导出 (17,408 B, 512B 扇区视图) — 仅留档
  gpt/tools/parse_gpt.py  GPT 解析脚本 (用于核对分区表)

------------------------------------------------------------------------------
一、为什么必须改 GPT（原理）
------------------------------------------------------------------------------
MediaTek 的 GenieZone（简称 GZ）是一套运行在 EL2 的安全虚拟化层。
本机 eMMC 的 GPT 里有两个专用分区:
    #39  gz1    LBA 0x43900 - 0x458ff   (8192 扇区 = 32.0 MB)
    #40  gz2    LBA 0x45900 - 0x478ff   (8192 扇区 = 32.0 MB)
preloader / LK 启动时会按分区名去查 GPT，把 gz1/gz2 里的 GZ 镜像加载起来，
于是 GZ 占住 EL2 —— KVM 需要 EL2，所以只打内核补丁（v8~v13）也不够，
KVM 仍然起不来。

办法: 让 LK 拿不到 gz 分区。工具 patch_gz_gpt.py 的默认模式会把
gz1/gz2 的 起始 LBA / 结束 LBA 改成越界地址 → LK 读 GZ 镜像时 I/O 失败
→ GZ 不加载 → EL2 让给 KVM。
(工具的另一种 --rename 模式是把分区名 gz 改成 gx，本机采用的是默认 LBA 模式。)

------------------------------------------------------------------------------
二、实际改了什么（与原厂逐字节比对结果）
------------------------------------------------------------------------------
cmp 统计: 共 22 字节不同, 位置全部落在 GPT 结构内:
  偏移 0x1010-0x1013  (4 B)   GPT 头 CRC32            ← 因内容改动而重算
  偏移 0x1058-0x105B  (4 B)   分区表项数组 CRC32       ← 因内容改动而重算
  分区条目 #39 gz1 的 FirstLBA(0x20-0x27) / LastLBA(0x28-0x2F) 被改写为越界值
  分区条目 #40 gz2 的 FirstLBA / LastLBA 同上
分区名称、类型 GUID、其它 50 个分区**均未改动**（strings 比对无差异）。

------------------------------------------------------------------------------
三、刷入命令（需要 root）
------------------------------------------------------------------------------
  推荐: 用包内脚本 (写前自动备份当前 GPT, 写后回读比对)
      cd <包目录>
      su -c "sh flash-gpt.sh"              # 刷入 NoGZ GPT
      su -c "sh flash-gpt.sh --restore"    # 还原原厂 GPT

  手动 (与当初实际执行的一致):
      su
      # 1) 先备份当前 GPT (前 256 KB)
      dd if=/dev/block/sdc of=/sdcard/gpt_backup_$(date +%s).bin bs=4096 count=64
      # 2) 写入改好的 GPT
      dd if=gpt/pgpt4k_nogz.bin of=/dev/block/sdc bs=4096 count=64
      sync
      # 3) 回读校验
      dd if=/dev/block/sdc bs=4096 count=64 | md5sum
      #    期望 c3fdbe48dccb5ceae2dfeebec1e87398
      # 4) 重启
      reboot

  要点:  /dev/block/sdc 是整块 eMMC 用户区；只写前 64×4096 = 256 KB
         (GPT 头 + 128 个分区条目)，不触碰任何分区数据。
         已实测: 设备当前 GPT 回读 MD5 = c3fdbe48… ✓

------------------------------------------------------------------------------
四、还原原厂 GPT
------------------------------------------------------------------------------
      su -c "sh flash-gpt.sh --restore"
  或  dd if=gpt/pgpt4k_orig.bin of=/dev/block/sdc bs=4096 count=64 && sync
      # 回读应为 5b4cffd99cf0d40e9038ba870024e985
  还原后 GZ 会重新加载，KVM 将再次不可用（但系统一切正常）。

------------------------------------------------------------------------------
五、验证 KVM 是否真的"有 EL2"
------------------------------------------------------------------------------
  1) 看内核是否报 KVM 初始化失败:
       dmesg | grep -i -E "kvm|hyp|geniezone|gz"
  2) 直接开一个 guest（见 README-FLASH.txt 第四节）:
       bash tools/verify_v9.sh
       期望: ===== GUEST INITRAMFS SHELL RUNNING ON KVM =====
  3) 若出现 "Failed to put registers" / KVM 无法创建 vCPU，先确认:
       dd if=/dev/block/sdc bs=4096 count=64 | md5sum   == c3fdbe48… ?
